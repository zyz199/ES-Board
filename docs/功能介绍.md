## 一、应用概览

### 1.1 定位

一个现代、轻量、跨平台的 Elasticsearch 图形客户端：安装包不到 10MB，通过 REST API 与 ES 通信，因此**基本不受 ES 版本限制**。核心目的不是"替代 Kibana"，而是把日常运维中最费手的一组操作（看指标、翻索引、改 mapping、调分词、写 DSL、做备份恢复）压缩成几个点击。

三大使用主线：

| 主线 | 涉及页面 |
|---|---|
| **看**（集群/节点/索引/文档/指标/健康/任务） | 节点、索引、文档、健康、指标、任务、诊断 |
| **改**（索引与文档的增删改、mapping/settings、别名、模板、ILM） | 索引、文档、模板、快照 |
| **查**（DSL 调试、REST 请求、分词验证） | REST、开发工具、分析 |

### 1.2 界面骨架

应用窗口由三部分组成，所有页面共享：

**① 顶栏（Header，固定 42px）**

- 应用图标 + 应用名
- **副标题徽章**：初始显示版本号（如 `更人性化的ES GUI 1.0.0`）；连接集群后变为 `当前集群: [集群名]`，并**随集群健康状态变色**（绿色健康 / 黄色警告），鼠标悬浮可见完整健康值
- **首页按钮**：在系统浏览器打开项目主页
- **检查更新按钮**：请求 GitHub 比对版本；有新版本时弹出可点击的「立即下载」提示；无网络时提示「无法连接 github，检查更新失败」（5 秒自动消失）
- **窗口控制**：最小化、最大化/还原、关闭（关闭按钮悬停变红）

**② 侧边栏（Aside，图标竖排）**

14 个页面的图标入口，当前页高亮。自上而下：集群、节点、索引、文档、REST、开发工具、分析、诊断、任务、健康、指标、快照、模板、设置。鼠标悬浮显示页面名。

**③ 内容区**

页面切换采用**首次访问才挂载、之后常驻**（keep-alive）策略：切走的页面用 `display:none` 隐藏而非销毁，因此已加载的表格数据、编辑中的表单、编辑器内容在来回切换时**不会丢失**。

### 1.3 全局机制

| 机制 | 说明 |
|---|---|
| **集群切换联动** | 在「集群」页点击某张连接卡片并连接成功后，广播 `selectNode` 事件，**所有已打开的页面会清空自身数据并重新拉取**，保证看到的是新集群的数据 |
| **手动刷新** | 各页面统一以「Refresh 按钮 + 集群切换自动重载」为刷新方式，**没有定时轮询**（避免大集群被客户端反复打） |
| **国际化** | 支持**简体中文（zh-CN）**与**English（en）**两种语言，在「设置」页即时切换 |
| **主题** | 明/暗两套主题，在「设置」页切换（对钩子暴露 `update_theme` 事件，代码编辑器主题会同步切换） |
| **确认弹窗** | 所有破坏性操作统一走全局确认对话框（取消 / 确认，危险操作确认按钮为红色），文案会说明具体后果 |
| **提示（Toast）** | 成功/失败/警告统一在顶部居中弹出 |
| **数据缓存** | 拉到的索引名列表会写入本地缓存（最多 1000 条），供各页面的索引下拉框与输入补全即时使用 |

## 二、页面功能详解

## 1. 集群 Cluster

**用途**：管理 Elasticsearch 连接——新增、编辑、测试、删除、导入导出，并选择当前激活的集群。**这是所有功能的前置页**，其他页面都依赖这里建立连接。

### 界面构成

- **标题行**：`集群` + 已保存连接数 + 三个按钮（`添加集群`、`导入配置`、`导出配置`）
- **连接卡片区**：4 列栅格，每张卡片显示连接昵称、地址（`协议://主机:端口`）、`已连接` 徽章，以及 `编辑`/`删除` 按钮。当前激活的卡片有绿色描边与徽章
- **编辑/新增抽屉**（右侧滑出，宽 38.2%，点击遮罩关闭）

### 连接字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 昵称（Nickname） | ✅ | 卡片上显示的名字 |
| 协议://主机:端口 | ✅ | 如 `http://localhost:9200` |
| 用户名 / 密码 | | 填写后自动启用 HTTP Basic 认证 |
| 使用 SSL | | 切换为 https |
| 跳过证书校验 | | 自签名证书场景使用 |
| CA 证书内容 | | 粘贴 CA 证书文本，用于校验服务端证书 |

### 操作清单

| 操作 | 行为 |
|---|---|
| `添加集群` | 打开抽屉（空表单） |
| `编辑` | 打开抽屉并回填该连接 |
| `测试连接` | 按当前表单内容试连，成功提示"连接成功"，失败给出具体原因（**不保存**） |
| `保存` | 校验必填项 → 写入配置文件 |
| `删除` | 二次确认后删除该连接 |
| **点击卡片** | **先测试连接，成功才激活**；失败只报错不激活。成功后自动跳到「节点」页 |
| `导出配置` | 弹出询问：**是否包含密码**（含密码 / 不含密码 / 取消）。导出为 JSON 文件，文件名带时间戳 |
| `导入配置` | 选择 JSON 文件导入 |

**导入的合并规则**（很实用）：

- 支持两种文件格式：顶层数组，或 `{ connects: [...] }`
- **同名连接原地更新**；不同名的追加
- `用户名`/`密码`/`CA 证书`**仅在新值非空时才覆盖**——所以可以用"不含密码的导出文件"批量改地址，而不会把已存的密码清空

### 安全设计

每次切换集群都会**重建 HTTP 客户端**，彻底避免上一个集群的 BasicAuth、TLS 设置、自定义 CA 证书残留到新连接。

## 2. 节点 Nodes

**用途**：一屏看清当前集群每个节点的运行压力。

### 表格列

| 列 | 含义 |
|---|---|
| 名称 / IP | 节点名与地址 |
| 角色 | 按角色字母映射为中文：主、数据、Ingest、ML、协调、远程、转换、热、温、冻、投票，多角色用 `/` 连接 |
| CPU 负载 | 5 分钟平均负载 |
| 堆内存占用 | `已用堆 / 最大堆` + 进度条 |
| 磁盘占用 | `索引存储 / 磁盘总容量` + 进度条 |
| 性能 | `Search` / `Merge` / `Segments` 三个徽章，**悬浮展开明细** |
| 系统 | `Process` / `FS` 两个徽章，悬浮展开明细 |
| 缓存 | 查询缓存、Fielddata、请求缓存、段内存 |
| 文档总数 / 段总数 | 千分位格式化 |
| 运行时长 | 如 `12天` |

**进度条阈值变色**：< 60% 绿色，60–79% 黄色，≥ 80% 红色。表格默认**按堆内存使用率降序**，压力最大的节点排最前。

**悬浮明细内容**（运维排查时最有用）：

- `Search`：查询总数/耗时、拉取总数/耗时、滚动总数/耗时
- `Merge`：合并总数/耗时、合并文档数、合并总大小、当前合并数
- `Segments`：段总数、总内存、Terms、Stored Fields、Doc Values、Norms
- `Process`：文件描述符（已用/最大）、进程 CPU、虚拟内存
- `FS`：总空间/可用空间、IO 读写操作数与流量

**导出**：`导出 CSV` → `es-nodes-{集群名}.csv`，含 15 个固定列 + 自动展开的 5 组统计明细列（列名形如 `Search - 查询总数`）。

## 3. 索引 Index

**用途**：索引全生命周期管理，功能密度最高的页面。

### 工具栏

| 控件 | 说明 |
|---|---|
| **模糊搜索框** | 输入关键词回车或点搜索图标检索（支持通配，如 `log*`） |
| `添加索引` | 新建索引（可基于模板） |
| `导出为 csv` | 导出当前列表 |
| `读取别名` | 批量拉取**当前页**索引的别名并填入「别名」列 |
| `索引备份（预览）` | 按 DSL 过滤后把索引数据下载为本地 JSON |

### 表格列

勾选列（多选）、**索引名称**（蓝色可点击，点击即查看前 10 条文档）、别名、健康（绿/黄/红徽章）、状态（open 绿 / close 红）、主分片、副本、文档总数、软删除文档、占用存储、操作。

### 行操作菜单（14 项，最核心的部分）

| 菜单项 | 行为 |
|---|---|
| 添加文档 | 打开 JSON 编辑框，索引名已预填 |
| 查看索引构成 | JSON 弹窗展示索引信息（mapping/settings/别名等） |
| 别名 | JSON 弹窗展示该索引的别名 |
| 查看10条文档 | JSON 弹窗展示前 10 条文档 |
| 管理别名 | 打开别名管理框（可将别名添加 Filter/Routing、也可移除别名） |
| 编辑 Mapping | 打开编辑器预填现有 mapping |
| 编辑 Settings | 打开编辑器预填现有 settings |
| Reindex 复制数据 | 源索引→目标索引的数据迁移（异步，含可选查询条件） |
| 段合并 | 强制合并段（**有性能影响，二次确认**） |
| 删除索引 | **二次确认**后删除 |
| 打开索引 / 关闭索引 | 按当前状态自动显示对应动作 |
| 刷新 | 执行 `_refresh` |
| Flush | 执行 `_flush` |
| 清理缓存 | 执行 `_cache/clear` |

### 各对话框要点

- **新建索引**：可选「从模板创建」下拉；填索引名（必填）、主分片数、副本数、mapping（JSON，会校验合法性）。选模板时改为「模板创建」接口
- **添加文档**：JSON 内容必填且需合法，成功后提示新文档 id
- **别名管理**：上半区列出已有别名（可逐个删除）；下半区填新别名 + 可选参数（如 `{"filter":...,"routing":"1"}`）
- **Reindex**：源索引只读、填目标索引与可选过滤条件；提示"后台异步执行，进度请到任务页查看"
- **编辑 Mapping**：顶部黄色警告——**只能新增字段或改 dynamic 参数，改已有字段类型会被 ES 拒绝**
- **编辑 Settings**：顶部蓝色提示——**仅支持可动态更新的项**（如副本数、刷新间隔）
- **索引备份（预览）**：填索引名 + 可选 DSL（留空=全量）+ **校验码**（QQ 群号 `964440643`，未填正确会中止下载）；成功后返回落盘文件路径

### 批量与分页

- 勾选多行后用「批量操作 → 删除」批量删除（有二次确认）
- 每页条数可选 5/10/15/20/25/30/40，**选择结果会被记住**

### 导出

`导出为 csv` → `index-list.csv`，9 列：索引名称、别名、健康、状态、主分片、副本、文档总数、软删除文档、占用存储。

## 4. 文档 Docs

**用途**：文档级操作——按 DSL 分页浏览、单条增删改、批量导入、按条件批量删除、字段统计。顶部三个 Tab。

### Tab 1：浏览（Browse）

- **工具栏**：索引下拉、刷新、Query DSL 输入框、`搜索`、`添加文档`、`导入`、`按条件删除`
- **结果表**：`_id` 徽章列 + **动态字段列**（从文档 `_source` 顶层字段取并集，最多 15 列，按"出现频率高的在前"排序）+ 操作列
- **行操作**：`详情`（只读弹窗）、`编辑`（可改 JSON 后保存）、`删除`（二次确认）
- **分页**：上一页/下一页 + `第 X-Y 行 / 共 N 行` + 每页 10/20/50/100 条
- **按条件删除**：**必须填写查询条件**（防止误删全库，源码显式拦截空条件）；二次确认后异步删除

### Tab 2：字段统计（Field Stats）

填「字段名」+「返回条数」（1–1000，默认 10），点搜索后：

- 若可用，额外显示 **Cardinality（基数）**：该字段有多少个不同取值
- 结果表：`取值` + `文档数`——即"这个字段都有哪些值、各有多少文档"，用于快速摸清数据分布

### Tab 3：导入（Import）

- **格式二选一**：`JSON` / `CSV`
- `选择本地文件`：选文件自动按扩展名切换格式并载入编辑器
- `填充示例模板`：一键填入 3 条示例数据
- 实时状态徽章：可解析时显示绿色 `N 篇文档可导入`，有错时红色报错
- CSV 规则：**首行是表头（字段名）**，其后每行一篇文档，支持双引号包裹与转义
- JSON 规则：必须是**对象数组**
- `开始导入`：经 `_bulk` 批量写入；部分失败会提示"成功 N 条、失败 M 条，首个错误：..."

## 5. REST 控制台 REST

**用途**：类 Kibana Dev Tools 的自由调试台，手写任意 ES 请求。

### 界面

- **查询 Tab 条**：可开多个 Tab 并行（各 Tab 独立保存方法/路径/请求体/响应），Tab 名 `Tab 1`、`Tab 2`…，超过 1 个时可关闭，右侧 `+` 新增
- **请求工具栏**：方法下拉（GET/POST/PUT/HEAD/PATCH/OPTIONS/DELETE）、路径输入框、`发送`、`历史记录`、`ES 查询示例`、`表格视图`、`导出结果`
- **双栏编辑区**：左侧**请求体编辑器**（带语法高亮与 DSL 自动补全），右侧**响应展示**（JSON 代码视图）

### 特色能力

| 能力 | 说明 |
|---|---|
| **路径自动补全** | 内置 26 个常用端点（`_search`、`_cluster/health`、`_cat/indices`…），并叠加本地缓存中的索引名及其 `_search`/`_mapping`/`_settings`/`_count` 变体 |
| **DSL 自动补全** | 50+ 关键词（query/bool/term/match/aggs/date_histogram/…）按前缀提示，输入时实时弹出 |
| **粘贴自动格式化** | 在请求体编辑器粘贴 JSON，自动整理成树状缩进 |
| **表格视图** | 响应可切换为表格：自动解析 `hits.hits`，把 `_source` 嵌套字段压平展开成列（最多 20 列） |
| **内置示例** | 15 个经典 DSL 一键插入：term / terms / match / match_phrase / range / bool / terms 聚合 / date_histogram / nested / exists / multi_match / wildcard / metrics 聚合 / cardinality / script |
| **历史记录** | 每次**发送成功**自动记录（方法、路径、请求体、时间）；右侧抽屉可搜索（按方法/路径/DSL）、分页浏览（每页 10 条，上限 100 条）、点击一键恢复 |
| **错误展示** | 后端返回错误时，能解析为 JSON 就格式化展示，否则原文展示 |
| **导出** | `导出结果` → 下载 `response.json` |

## 6. 开发工具 Dev Tools

**用途**：针对**批量请求**优化的控制台——一个编辑器里写多条请求，逐条执行并逐条看结果。相比 REST 页，它更适合"一次跑一组诊断命令"。

### 脚本语法

```
# 集群健康              ← 以 # 开头的行是注释，同时充当请求分隔符
GET /_cluster/health

# 查看索引列表
GET /_cat/indices?v

# 搜索
POST /_search
{
  "query": { "match_all": {} },
  "size": 10
}
```

规则：`方法 /路径` 为请求行，紧随其后到下一请求行之前的内容是请求体。

### 界面

- **工具栏**：`执行`、`全部执行`、`清空结果`、`示例` 下拉、`历史记录`，右侧显示「请求数: N」
- **左栏编辑器**：自定义 Ace 语法高亮（注释、HTTP 方法、JSON 键/值、数字、布尔、路径各有着色）；**每个请求的首行贴一个行内播放按钮**，可单独执行该条
- **右栏响应区**：每个请求一张卡片，显示方法徽章、路径、执行状态（`OK`/`ERROR`）、**耗时（毫秒）**、复制按钮与响应内容。未执行的显示"尚未执行"

### 操作

| 操作 | 说明 |
|---|---|
| `执行` | 执行**光标所在**的请求（无则提示写法） |
| `全部执行` | **按顺序串行**执行所有请求（避免把集群打爆） |
| `清空结果` | 清空右栏 |
| `示例` → 6 个内置请求 | 集群健康、索引列表、搜索请求、聚合请求、索引 mapping、分片分配；点击**追加**到编辑器 |
| `示例` → `重置编辑器` | 恢复默认脚本 |
| 历史记录 | 仅记录**执行成功**的请求，同方法+路径+请求体自动去重，上限 100 条，每页 10 条，点击插回编辑器 |

### 编辑体验

- 自动补全：请求行提示 API 路径，请求体提示 DSL 关键词
- 脚本**自动保存**（400ms 防抖），关掉应用再打开内容还在
- 跟随主题切换编辑器配色

## 7. 分析 Analyze

**用途**：分词调试器，验证某个索引/分词器把一句话切成了什么。

### 界面与操作

- **索引下拉** + 刷新（决定用哪个索引的分词配置）
- **Analyzer 输入框**：带 13 个预设建议——`standard`、`simple`、`whitespace`、`stop`、`keyword`、`pattern`、`english`、`french`、`german`、`cjk`、`ik_max_word`、`ik_smart`、`pinyin`
- **Field 输入框**：填了字段就用该字段的分词器，**并会覆盖上面的 Analyzer**（此时 Analyzer 框禁用）
- **文本输入框**：回车即分词，`Shift+Enter` 换行
- **结果表** 5 列：分词结果（Token）、词元类型（Type）、位置（position）、起始偏移、结束偏移

典型用法：验证中文分词效果（`ik_max_word` vs `ik_smart`）、排查某个查询为什么匹配不到。

## 8. 诊断 Diagnose

**用途**：集群运维排障面板。四个 Tab + 一个弹窗。

### Tab 1：分片列表（Shards）

- 说明条提示：为避免大集群 Master 序列化压力，**不会自动加载全部分片**
- 工具栏：按索引过滤（支持 `*`）、按状态过滤（全部 / STARTED / INITIALIZING / RELOCATING / UNASSIGNED）、`搜索`、`查询全部分片`（**有确认提示，大集群慎用**）、`解释未分配分片`
- 表格 9 列：索引、分片号、角色（主/副本，彩色徽章）、状态（按状态着色）、文档数、存储大小、所在节点、节点 IP、操作（`解释`按钮）
- **分片分配解释**：点「解释」或「解释未分配分片」后弹出说明，直接告诉你"这个分片为什么没分配/不能移动"及官方指引——**排障利器**

### Tab 2：线程池（Thread Pools）

按池/节点名过滤，表格：节点名、线程池名（write/search/get…）、活跃数、排队数、**拒绝数**、线程数、类型。

> 关注点：`Rejected` 持续增长说明集群过载，需要扩容或限流。

### Tab 3：热点线程（Hot Threads）

- 选择节点后 `开始采样`；默认是「所有节点（高开销）」——**选全集群会弹确认框**，因为会并发触发所有节点的 JVM 栈采样
- 结果以等宽文本展示 CPU 占用最高的线程堆栈

### Tab 4：挂起任务（Pending Tasks）

`刷新` 后表格展示主节点当前排队/被阻塞的任务：插入顺序、优先级、动作、排队时长。

## 9. 任务 Task

**用途**：查看集群正在运行的任务，并终止可取消的任务。

- **筛选行**：三个输入框（任务 ID / 节点 / 动作）+ `搜索`（前端模糊匹配）+ `导出 CSV`
- **表格 10 列**：任务 ID、父任务 ID、节点、IP、类型、动作（徽章）、开始时间、运行时长、是否可取消（可取消为红色徽章）、操作
- **终止任务**：点行内 `终止`，成功后右侧抽屉展示后端返回的 JSON，并自动刷新列表。**不可取消的任务按钮为禁用态**
- **本页无自动刷新**，需要手动点 `刷新`

典型场景：Reindex、批量删除、快照恢复跑起来后，来这里确认任务在跑、或中途取消。

## 10. 健康 Health

**用途**：集群健康的完整指标表。

15 项指标（中文释义 + 彩色徽章 + 原始字段名）：集群名、**健康状态**（绿/黄/红）、是否超时、节点数、数据节点数、活跃主分片数、活跃分片总数、重定位中/初始化中/**未分配**/延迟未分配分片数、待处理任务数、进行中抓取数、队列最长等待时间、活跃分片百分比。

**联动**：本页拿到健康状态后，会把颜色同步到**顶栏徽章**，所以在任何页面都能一眼看到集群是否健康。

> 最常看的两个值：`未分配分片数`（> 0 说明有分片没起来）和 `健康状态`。

## 11. 指标 Metrics

**用途**：`_cluster/stats` 的全量指标浏览，带**中文释义**。

- 六个可折叠分区：节点、内存、索引、文档、分片、存储
- 每个分区一张三列表：**中文说明**（悬浮看原始 key）、数值、原始 key（如 `indices.docs.count`）
- 覆盖范围很广：索引/文档/存储总量、字段与映射统计、查询缓存命中与驱逐、段内存分布（Terms / Doc Values / Norms / Stored Fields / 点）、分片的平均/最大/最小数、节点角色计数、JVM 堆、操作系统内存与 CPU、索引压力（indexing pressure）等

> 用途：给集群做"体检"、写容量报告、找内存占用大头（比如 fielddata 或 query cache 异常增长）。

## 12. 快照 Snapshot

**用途**：备份与恢复中枢。**五个 Tab**。

### Tab 1：仓库（Repository）

- 表格：仓库名、类型、配置（JSON）、操作（`验证` / `删除`）
- `创建仓库`：填仓库名 + **类型（6 种）** + 配置 JSON
  - 支持类型：`fs`（共享文件系统）、`s3`、`hdfs`、`azure`、`gcs`、`url`
  - ⚠️ 各类型的参数（如 fs 的 `location`、s3 的 `bucket`/`base_path`/`region`/密钥）**需要手写在配置 JSON 里**，界面不按类型动态生成表单
- `验证`：确认所有节点都能访问该仓库
- `删除`：确认框说明"已有快照数据文件不会被删除，只移除集群里的仓库注册"

### Tab 2：快照（Snapshots）

- 列表按开始时间倒序；列：快照名、仓库、状态（成功绿 / 失败红 / 进行中蓝）、开始/结束时间、索引数、总分片数、成功分片数、操作
- `创建快照`：选仓库、填快照名、填索引（逗号分隔，**留空=全部索引**）、是否包含集群全局状态；提示"后台异步创建，请刷新查看进度"
- 行操作：`详情`（JSON 弹窗）、`去恢复`（自动把该快照带入恢复表单并跳到恢复 Tab）、`删除`

### Tab 3：恢复（Restore）

- 表单：仓库 → 快照（**只列出状态为成功的**）、索引（逗号分隔）、**重命名正则 + 替换表达式**（如 `index_(.+)` → `restored_index_$1`，用 `$1` 反向引用）、是否恢复全局状态
- 页面上有醒目警告：恢复会在集群里创建索引；**若同名索引已存在且未关闭会失败，建议用重命名避免冲突**
- 提交前有二次确认；表格实时展示恢复进度：索引、分片、类型、**阶段**（DONE 绿 / INDEX 蓝 / 其它黄）、源节点、目标节点、**进度百分比**

### Tab 4：SLM 自动快照策略

- 表格：策略 ID、仓库、Cron 计划、快照命名模板、下次执行、上次成功、上次失败（失败用红色徽章高亮）、操作（`立即执行` / `删除`）
- `创建策略`字段（含默认值）：策略 ID、快照名模板（默认 `<daily-snap-{now/d}>`）、**Cron 计划（默认 `0 30 1 * * ?`，需手写 Quartz 六段式）**、仓库、索引范围、`Expire After`（默认 `30d`）、最少保留数（默认 5）、最多保留数（默认 50）

### Tab 5：ILM 索引生命周期

- 表格：策略 ID、阶段（hot/warm/cold/delete）、被哪些索引使用、修改时间、操作（`详情` / `删除`）
- `创建 ILM 策略`：策略 ID + 策略 JSON（含 hot/delete 阶段示例）；对话框底部说明 ILM 会自动执行 rollover、shrink、delete 等操作

> ⚠️ 注意：快照创建与恢复**不会自动刷新进度**，需要点 `刷新`。
